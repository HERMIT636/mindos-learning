# CANN 环境、版本与工程流程

本讲义为 MindOS 原创课程草稿，尚待教师审核。先理解现象与条件，再尝试完整例子。

## 为什么要学

同样的 Ascend C 代码在不同 CANN 版本、芯片型号或算子工程方式下，API 和约束可能不同。先建立可复现的工程与运行环境，避免把安装或接口不匹配误判为算法错误。

## 核心原理

记录芯片型号、驱动、固件、CANN 版本、编译器和运行方式，按对应版本的官方文档构建样例。入门可先跑通官方 Add 类最小示例：生成或创建工程、编译核函数、运行、比对。区分主机侧的算子描述和 tiling 准备与设备侧核函数；编译成功只说明语法与链接通过，不代表数值或性能通过。

## 逐步例子

先在指定环境运行一个已知正确的最小 Add 示例，保存命令、输入、输出和版本号。再只改动一个地方，比如元素数 N，从完整块变成带尾块，确认构建和对拍仍成功。如果示例都跑不通，先查环境与版本，暂不要叠加优化。

## 常见误区与自查

不要混用不同文档版本的代码片段，也不要把编译通过称为通过上板测试。自查安装路径、环境变量、编译目标、设备可见性和最小运行记录。

## 学完后的检验

先合上讲义，自己复述：这个方法解决什么问题、前提是什么、例子中的每一步为何成立、换一组输入时哪些判断必须重做。再完成两道不同的公开练习；练习表现只是初步证据，不能代替真实项目中的实现与复核。
