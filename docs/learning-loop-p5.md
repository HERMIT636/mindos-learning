# Learning Loop P5：自适应学习执行与节奏建模

P5 在已有成长路线、课程、复习和检测之上记录用户主动执行的学习时段，以个人完整任务记录调整耗时建议，并比较时间预算与实际记录。课程章节、知识原子、独立证据、掌握判定和成长路线能力要求保持原有职责。

## 使用

1. 在驾驶舱“今天学习”打开建议任务，或进入任意课程。页面访问不会开始计时。
2. 点击“开始本次学习”，顶部出现学习记录条。可暂停、继续、隐藏时间或回到本次课程。隐藏时间不停止记录。
3. 点击“结束本次学习”，选择本次完成情况和原因；忘记暂停时可以修正实际分钟数。结束的是这次执行，成长任务仍需真实学习结果才可完成。
4. 在“学习执行记录”查看、按日期筛选、分页、修正或删除错误记录。修改和删除后，个人估时缓存会失效并从最近记录重建。
5. 成长路线中查看“计划与实际节奏”，必要时先编辑目标日期、每周可用时间或能力范围，再明确点击原有重新规划操作。风险提示不会自动修改目标或删除内容。

课程、复习、跨课程确认、课程终局检测、开放实践和成长任务入口都会给出可选计时建议。创建课程建议也可作为目标任务主动计时。自由进入课程时允许不关联目标；从目标任务开始时只关联启动它的一个目标。

## 数据与恢复

- `StudySessionService` 保存学习记录；`task_execution_events` 只保存执行事件，绝不是 P0 学习证据。
- 同一用户最多一条 active 记录，数据库有唯一约束；第一版还要求先处理已有 paused/interrupted 记录，再开始新记录，防止遗落多个计时器。
- 暂停区间单独累计，不计 active time。页面只对用户已开启的记录发存活检查点，不读取页面焦点、输入、系统窗口或其他应用。它不能证明用户始终专注。
- 刷新/短暂重开仍可读取当前记录。检查点超过 180 分钟未恢复时，标记 interrupted，只保留最后有效检查点累计的时长，不追加长时间离线区间。可继续、结束或修正；曾中断记录保持中断标记，不参与完整任务估时。
- 240 分钟以上结束需明确确认或修正；异常长记录保留历史，但不用于个人 Pace Model。
- 普通区间按本地日期/周边界拆分，避免跨午夜全部算给同一天。手动修正的总时长按记录开始日期归属，这是第一版可解释的简化。
- 所有记录都在本机 SQLite。课程/目标使用软引用；删除目标或回收课程不阻塞或删除已保存执行历史。结束时只观察当前课程范围已有答题结果，不产生新证据。

## 个人估时

`PersonalPaceModel` 按活动类型和 short/medium/long 分桶，使用最多最近 60 条结束记录的中位数、10% 截尾均值和 P75。有效记录要求本次安排完成、有效基准分钟数、合理实际时间、未中断、未放弃、未标记无效、比值在 0.2～4.0 之间。部分执行不能当作完整任务耗时，否则会让模型误以为任务更快。

`planned_minutes` 在本版表示本次任务的初始基准分钟，原始 `base_minutes` 与运行时 `predicted_minutes` 同时保留。前端开始时提交基准而不是已经调整过的预测，避免“预测后的时间再次当基准”造成反馈漂移。自由课程/检测采用对应活动的初始规则值。用户设置的实际修正只改执行记录，不覆写 P4 Task 的 `estimated_minutes`。

少于 3 条完整样本时仍用规则估时，界面明确“完整记录不足”；3～9 条为 medium，10 条以上为 high。预测倍率限制在 0.6～2.0。high 仅表示样本较多，绝不是经过外部检验的预测准确率。

缓存保存 `source_cursor` 和策略版本；只有有效历史发生变化时才从每类最多 60 条记录重建，不随每次页面读取全量扫描所有历史。事件编号单调递增，删除也显式失效缓存，避免删除最高事件编号后误用旧快照。调试统计仅在 `MINDOS_DEBUG_LEARNING=1` 可读；普通接口只返回通俗摘要。

## 今日负载与截止参考

`AdaptiveDailyLoadPlanner` 复用 P4 当前阶段 ready/active 任务和 P0 复习队列，依次优先复习、未结束记录、关键/前置能力、完整检测、实践与可选任务。多目标有关键任务时尽量覆盖不同目标，紧急复习仍优先。最多 3 个今日任务，8 个本周优先任务。

每周参考 5 个学习日；有预算时扣除已记录实际时间，并同时受本周剩余预算约束。多个目标的周预算不简单相加，继续用较小预算作为保守的共享时间上限。无预算时仅按优先级选最多三项。

只有课程学习和小练习可建议“今天先学一段”。跨课程验证、Final 和 Authentic 不截断为剩余几分钟；预算不足就保留到下次。结束一段计时不完成任务。计时显示默认累计已用时间，不施加倒计时压力。第一版未实现可选 timebox 通知。

`PlanRealityAnalyzer` 显示本周及最近各周预算、实际记录、会话结束/部分完成与任务延续情况，区分 P4 成长任务的真实完成比例。反复三次放弃只提示执行摩擦，不推断知识能力或人格。剩余工作包含已跳过但仍要求完成的关键任务，跳过不能降低能力要求。

截止参考优先使用最近两个完整观察周的主动记录容量；不足时仅以预算参考并显示 insufficient_data。结果是 on_track / at_risk / unlikely / insufficient_data，没有完成概率，不承诺具体完成日期。未确认路线或过期路线不判断可行性。预算和历史都是本机工程参考，并非对真实全部学习活动的测量。

## 接口

| 接口 | 用途 |
|---|---|
| POST `/api/study/sessions/start` | 明确主动开始；课程或成长任务上下文由服务器校验 |
| GET `/api/study/sessions/current` | 刷新恢复和异常中断检查 |
| POST `/api/study/sessions/{id}/pause`、`resume`、`checkpoint`、`end` | 暂停、继续、存活检查、结束 |
| GET `/api/study/sessions` | 日期、课程、目标筛选，游标分页，最多 100 条 |
| PATCH `/api/study/sessions/{id}` | 修正已结束记录实际时间 |
| DELETE `/api/study/sessions/{id}` | 删除错误执行记录，不删除学习结果 |
| GET `/api/study/pace` | 通俗个人估时摘要 |
| GET `/api/debug/learning/pace` | 明确开发开关开启后的统计 |
| GET `/api/growth/today` | 基准与个人估时、预算剩余、最多三项建议 |
| GET `/api/goals/{id}/execution` | 计划偏差、截止风险与重规划建议 |

所有查询、操作和课程/任务关联都验证当前 cookie 用户所有权；写接口沿用本机 Origin/Host 检查。现有本机 cookie 边界仍不是生产多用户认证。

P4 Task start 只附 `study_session_suggestion`，不会偷偷创建会话。P4 stage organization 如接收 `pace_context`，只有预算、观察容量范围、截止风险及边界四个字段；不发送完整执行历史。模型不得改掌握结论、能力要求或程序顺序。

## 完成自审（PRD 22 项）

| 项目 | 答案与验证 |
|---|---|
| 1 主动开始 | 是；页面访问及打开成长任务不创建记录，API 和浏览器验证。 |
| 2 后台电脑监控 | 无；没有焦点、键鼠、窗口、录屏、摄像头或系统活动采集。 |
| 3 暂停排除 | 是；15 + 暂停10 + 12 = active27 / pause10。 |
| 4 刷新恢复 | 是；SQLite current，浏览器 paused 刷新、active 关闭重开。 |
| 5 中断排除离线 | 是；last_checkpoint 超阈值只保留已累计时长。 |
| 6 单一 active | 是；唯一索引、写事务和并发测试。 |
| 7 不修改 KnowledgeState | 是；执行长/短/多暂停/放弃的数据库快照测试。 |
| 8 Pace 不影响 mastery | 是；执行模块没有知识状态写入；11 个冻结文件 SHA 一致。 |
| 9 Session 完成不完成任务 | 是；结束27分钟后 GrowthTask 仍 active，Gap 保持原值。 |
| 10 异常排除 | 是；中断、放弃、部分执行、异常比值、错误与超长记录排除。 |
| 11 样本不足 | 是；规则 fallback，有通俗提示。 |
| 12 今日个人耗时 | 是；20→28 单测及25→35浏览器更新。 |
| 13 今日最多三项 | 是；今日3/本周8测试。 |
| 14 多目标覆盖 | 是；两个 critical 目标尽量各选一项，复习优先。 |
| 15 实际节奏风险 | 是；每周150对预算300、剩余800的 unlikely 场景。 |
| 16 不自动删关键能力 | 是；只读分析，跳过关键任务仍算剩余工作。 |
| 17 只建议 P4 | 是；无自动 replan 调用；需用户操作原 P4 界面。 |
| 18 冻结 | 是；state/policy、P1、P2、P3、growth_gap/growth_graph SHA 保持。 |
| 19 修正删除刷新 | 是；游标、失效和删除最高事件编号回归。 |
| 20 快慢不等于掌握 | 是；执行条、记录与模型上下文明示。 |
| 21 本地保存 | 是；SQLite，无云端执行遥测。 |
| 22 不评价生产力人格 | 是；界面仅记录时间差异和条件，模型提示明确禁止。 |
