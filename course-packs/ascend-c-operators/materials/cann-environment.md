# CANN 环境、版本与工程流程

这是从零开始的 MindOS 课程草稿，尚待教师审核。读不懂某个词时，先看下面的术语，再按步骤阅读；无需先会做题。

## 第 0 步：先认清本讲的词

- **CANN**：昇腾的软件开发与运行工具体系。
- **版本**：一组确定的接口与兼容范围。
- **编译**：把源代码转换为设备可执行形式。

## 第 1 步：从一个问题出发

同样的 Ascend C 代码在不同 CANN 版本、芯片型号或算子工程方式下，API 和约束可能不同。先建立可复现的工程与运行环境，避免把安装或接口不匹配误判为算法错误。

## 第 2 步：理解它怎样工作

记录芯片型号、驱动、固件、CANN 版本、编译器和运行方式，按对应版本的官方文档构建样例。入门可先跑通官方 Add 类最小示例：生成或创建工程、编译核函数、运行、比对。区分主机侧的算子描述和 tiling 准备与设备侧核函数；编译成功只说明语法与链接通过，不代表数值或性能通过。

## 第 3 步：跟着例子做

先在指定环境运行一个已知正确的最小 Add 示例，保存命令、输入、输出和版本号。再只改动一个地方，比如元素数 N，从完整块变成带尾块，确认构建和对拍仍成功。如果示例都跑不通，先查环境与版本，暂不要叠加优化。

### 1. 先核对版本

先记录设备型号、驱动、CANN 版本与对应文档。示例若使用另一版本的 API，先查该版本是否支持，不要把编译错误一概当成自己写错语法。

### 2. 建立最小工程

先用官方当前版本示例完成编译、运行和一次正确性检查，记录成功命令与输出。这个基线能帮你区分环境问题和后续算子逻辑问题。

## 常见误区与自查

不要混用不同文档版本的代码片段，也不要把编译通过称为通过上板测试。自查安装路径、环境变量、编译目标、设备可见性和最小运行记录。

## 自己试一试

示例代码与本机 CANN 版本不同，为什么应先核对接口而不是直接复制运行？

先不用急着做正式练习。能用自己的话说清这道小检查，才进入下一讲；答不出来就回到第 2、3 步。后面的公开练习只提供初步证据，不能代替真实项目中的实现与复核。
