# Learning Loop P4：目标驱动的成长路线

P4 从用户长期目标出发，比较目标能力与 P0～P3 的实际学习结果，建议下一步学习、复习、验证或实践。它是规划层，不是第二套课程、复习或掌握算法。

## 使用流程

1. 在「成长路线」填写目标、希望独立完成的事情，以及可选截止日期和每周时间。
2. 审查能力草稿：编辑、删除、增加自定义能力，检查前置关系，再确认。
3. 查看缺口及路线，打开当前任务。已有课程优先；新课程建议仍须经过原有大纲审查与用户确认。
4. 在原有课程、独立检测或开放任务中学习。返回成长路线检查结果；重大变化生成新版本并说明原因，旧版本保留。

暂停目标会移出今日建议。跳过、暂停、固定或优先显示任务，不会改变能力依据或自动满足目标。用户重新加入此前移除的能力后，不会被后续分析再次过滤。

## 架构和数据边界

`Goal → Capability Graph → Gap Analysis → Growth Planner → Roadmap → 原有学习入口 → Progress Evaluation → Replanning`

- `growth_graph.py`：目标能力 JSON schema、一次修复、保守可编辑 fallback、前置循环校验，以及复用 P3 语义判定的课程知识关联。能力要求与用户现状分离。
- `growth_gap.py`：按用户批量读课程、有效 P3 映射、独立答题状态、误区、校准与复习队列；在内存调用原 P3 聚合函数。P1 状态按课程读取一次，不为每项能力查询 SQL，不写个人档案缓存。
- `growth_planner.py`：程序决定任务、依赖、优先级、完成条件和时间估计。模型仅组织阶段标题和分组；必须保留程序顺序，不能重排任务。失败时使用规则分组。
- `growth.py`：目标生命周期、版本化路线、任务操作、课程和开放任务的显式关联、完成检查、今日建议。
- `growth_api.py` 与原生前端 `components/mindos/growth.js`：独立接口和页面，保持原有课程布局与课程内星图。

新增五张表：`learning_goals`、`goal_capability_mappings`、`growth_roadmaps`、`growth_tasks`、`growth_roadmap_changes`。能力与依赖合并保存为目标内 JSON。没有全局知识图谱，不做跨用户推荐。

规划只能写 P4 表。打开独立题目或提交回答后，仍由原有 P0～P3 服务写学习结果。P4 本身不写 KnowledgeState、LearningEvidence 或 PersonalKnowledgeProfile，不直接修改知识原子，也不推进章节。

## 缺口、关联与门槛

区分 `missing`、`unknown`、`partial`、`ready_to_verify`、`sufficient`、`stale`、`conflicted`、`practice_missing`。未测维度保持未知；过去较强的基础用于快速确认，不能复制为新课程掌握。

候选关联不算课程覆盖。审查时显示原知识定义、类型和领域；用户可确认或拒绝。新增课程的知识图谱形成后，点击「检查新增课程的知识关联」，保持用户已拒绝的关联不被自动恢复。

现有课程包含尚未开放的内容时，任务进入课程当前进度，不跳到未来小节。回收站或永久删除的课程会阻塞任务。复制课程不复制成长路线关联。用户确认创建建议课程后，可记录入口关联并继续该课程；入口关联本身不证明能力覆盖或掌握。

关键能力及其硬前置都要有足够依据。课程内容完成但路线选中的课程 P1 检测未满足时，仍需终局检测；无关历史来源课程的未完成检测不会无限阻塞目标。关键冲突与误区不能静默视为满足。跳过任务不改变门槛。

项目或比赛还需要目标内实践要求。开放任务复用 P2，并带服务器校验的目标能力范围；只接受对应目标、对应能力、当前要求指纹和独立性有效的结果。无关开放成绩、使用提示的成绩或旧范围成绩不能满足本次实践要求。模型辅助评分仍不是独立事实或职业认证。

修改目标范围后，能力要求也需重新确认。截止日期等规划条件变化会使旧路线失效；不能继续执行旧任务。P4 用规则显示「当前目标要求已基本满足」，而非资格认证。

## 版本、解释和预算

重大调整写新路线版本、触发原因、任务增减、缺口变化、输入指纹和策略版本；任务元信息保留具体决策理由。旧版本只读回顾，不能执行。

检查结果或返回路线时，程序可对重大状态变化自动重规划。默认间隔 600 秒；期间更新任务状态并提示可主动重新规划。普通小测提交不会直接调用重规划。主动重新规划不受该间隔限制。目标或能力要求变更须用户先确认。

今日重点最多三项，合并原复习队列、当前成长任务和正在学习的课程。分钟数是规则估计；设置预算时控制今日和每周建议总量，多目标暂采用最小预算保守安排。未设置预算时只按优先级展示。不是严格日程系统，也未统计真实耗时。

ATIE 与课程导师仅读取当前目标、阶段目标、任务关联三个简短字段，原课程教学范围仍有效。导师不能修改路线。课程规划只获取当前能力缺口范围，仍保留必要基础和完整章节。

## 接口

- `GET/POST /api/goals`；`GET/PATCH/DELETE /api/goals/{id}`。
- `GET /api/goals/{id}/{capabilities,gaps,roadmap,status}`，路线支持 `?version=`。
- `POST /api/goals/{id}/analyze`：生成草稿，或提供草稿版本与 `confirm: true` 确认编辑后的结构。
- `POST /api/goals/{id}/{roadmap/generate,replan,evaluate,capabilities/scan}`。
- `POST /api/goals/{id}/mappings/{mapping_id}/{verify,reject}`。
- `POST /api/goals/{id}/tasks/{task_id}/{start,skip,pause,resume,lock,pin,artifact,link-course}`。
- `GET /api/growth/today`。`MINDOS_DEBUG_LEARNING=1` 时开放 `/api/debug/learning/growth/{id}/...`；普通缺口界面不显示内部数值。

目标、任务与引用课程都校验用户归属。不能由客户端提交评分、掌握率或 achieved。草稿确认使用版本比较，目标修改或并发重规划后，过期请求不得覆盖新结果。

## 验证

最终记录见 [自动化与浏览器结果](validation/learning-loop-p4-2026-10-02.json) 和 [真实模型与合成状态结果](validation/learning-loop-p4-real-2026-10-02.json)。真实模型验证可用 `scripts/check_growth_model.py` 显式指定模型配置数据库、密钥文件和报告路径复现；脚本只读取模型配置，全部学习状态为合成数据，密钥不回显。

```bash
python3 -m unittest discover -s tests -v
python3 scripts/check_browser.py growth
```

工程启发式位于 `growth_policy.json`。路线合理运行不代表已证明是最优教育路径；当前未做真实用户长期教育效果实验，LLM 能力拆分与开放评分也不是权威认证。

## 最终自审

|项|结论与证据|
|---|---|
|1. Planner 写 KnowledgeState？|否；非 P4 表快照测试保持完全一致。|
|2. Gap 来自实际结果？|正式入口批量读 P0～P3；需求能力是比较基准，未知不补分。|
|3. LLM 判断已掌握？|不接受；严格要求 schema 不允许 mastery 等现状字段。|
|4. 优先复用已有课程？|是；已确认 P3 覆盖与用户创建入口均有测试。|
|5. strong prior 优先验证？|是；高要求进入独立验证，不自动复制掌握。|
|6. stale 优先复习？|是；复用原复习与遗忘投影，路由测试覆盖。|
|7. conflict 优先验证？|是；P3 冲突和已确认误区阻塞后续能力。|
|8. P1 未完成仍要求 Final？|是；只检查路线选中的相关课程，保持 P1 原规则。|
|9. 缺少 P2 实践能安排 Authentic？|是；显式绑定目标实践范围及结果，旧或无关成绩无效。|
|10. dependency 严格有效？|硬前置拓扑顺序、阶段顺序和启动门槛同时校验。|
|11. 阻止 prerequisite cycle？|是；硬循环拒绝，软冲突安全忽略并提示。|
|12. 修改目标使旧路线 stale？|是；改范围还须重确认能力，不能执行旧任务。|
|13. Major Replan 版本化？|是；新版本、新任务，旧记录保留。|
|14. 明确调整原因？|是；原因码、任务增减、缺口变化、输入指纹和策略记录。|
|15. Planner 不推进章节？|是；实际独立测验后进度仍为原小节，浏览器验证。|
|16. Today 不塞大量任务？|最多三项，预算估计受规则约束。|
|17. 无第二套课程系统？|所有任务进入原课程与大纲审查接口。|
|18. 无第二套 Review？|复用 ReviewScheduler.queue 与 ForgettingService.project。|
|19. 不复制 P3 mastery 到 Capability？|能力只存要求；缺口为只读计算，没有掌握写入字段。|
|20. P0～P3 全量回归？|最终测试数量及结果记录于验证 JSON，冻结文件逐项 SHA 检查。|
|21. 真模型阶段经过依赖校验？|是；两项合成目标均校验硬依赖与程序顺序，不合规时修复一次或规则回退。|
|22. 声明非最优教育路径？|本页和界面明确说明；没有宣称教育或职业认证。|
