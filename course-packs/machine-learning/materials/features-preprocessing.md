# 特征、缺失值与预处理流水线

本讲义为 MindOS 原创课程草稿，尚待教师审核。先理解现象与条件，再尝试完整例子。

## 为什么要学

模型看到的不是抽象概念，而是具体数字或编码。特征的单位、缺失原因和类别编码会影响学习结果；错误预处理甚至能产生看似出色却无法部署的模型。

## 核心原理

区分数值、类别、文本与时间特征。缺失值可以用训练集统计量填补，但要记录缺失本身可能携带的信息；类别变量编码方式要和模型假设一致。流水线把拟合与转换步骤封装在一起，让每个交叉验证折只用自己的训练部分估计参数。特征工程应从业务可用性、可解释性和泄漏风险出发。

## 逐步例子

预测设备是否故障时，温度为数值、机型为类别。先把训练集的温度中位数用于填补缺失，再把机型做独热编码；验证集只能调用已拟合的填补器和编码器。若某个“维修完成日期”字段在故障发生后才产生，它即使与标签高度相关，也必须删除。

## 常见误区与自查

不要把类别编号 1、2、3 直接当作有大小关系的连续量，除非业务确有顺序。不要先把全表标准化再交叉验证。自查时列出每步预处理的 `fit` 数据范围、输出维度以及未知类别的处理方式。

## 学完后的检验

先合上讲义，自己复述：这个方法解决什么问题、前提是什么、例子中的每一步为何成立、换一组输入时哪些判断必须重做。再完成两道不同的公开练习；练习表现只是初步证据，不能代替真实项目中的实现与复核。
