# MindOS 讲解稿与检索策略

## 先解决教学内容

MindOS 的主要教学单元应是一篇经过复核的基础讲解稿，而不是一个知识点标题、几段提纲或检索结果。当前三门主课程虽有 25 篇逐步讲义，深度仍不足以称为完整的零基础教材。下一轮优先用真实学习对话打磨讲解稿，保留提问暴露出的不理解之处，再编辑成可独立阅读的课程内容。

每篇稿件至少交代：学习者已知条件、本讲目标、新术语的白话解释、一个逐步推导或可运行例子、每一步为什么成立、反例与常见误解、带解释的即时自查、进入下一讲的标准。若涉及代码、公式或设备接口，应实际运行或人工核对。学习对话的记录是草稿，不直接等于审核通过的教材；补充原始来源、版本和审核记录后再发布。

公开讲义与公开练习可以用于教学检索。独立测评题、评分答案和隐藏测试单独保管，不放进教学资料或向量索引。

## 当前原型里“RAG”实际做了什么

- 资料模式的提问按知识点范围和关键词，从课程 Markdown 和 MindOS 撰写的外部资料导读中选相关片段并显示出处。它不会生成新的讲解。
- 大模型模式的提问可在上述片段和已整理导读的候选集合中检索；只有配置了 Embedding 模型，才会计算向量并与关键词分数合并。向量缓存在本地 SQLite 中；当前没有独立的向量数据库或离线构建的完整教材索引。
- 正式讲解页直接读取当前知识点的整篇本地讲义。大模型模式会把该知识点的片段作为参考交给模型；讲解页当前不通过向量排名来决定教哪一讲。
- 现有十二则外部资料导读覆盖 Python、线代、机器学习及 Ascend C，其中机器学习七则、Ascend C 一则。HPC 暂无外部导读。下载在审核工作区的原始 HTML/PDF 没有自动进入索引；公开仓库只附中文导读、来源目录和原文链接。新导读经过文件完整性与主题初审，教学内容仍待教师审核。

因此，现在扩大向量库不能自动解决“初学者听不懂”的问题。先做扎实的讲解稿，再按知识点补充可信的参考材料；用真实学习者问题检查“按知识点＋关键词”找不到什么。只有资料规模和问法复杂到这种方式持续漏检，才为主课程构建并评估向量索引。评价至少比较相关片段命中、引用正确性、回答是否真正解惑，以及成本与维护量。

## 后续讲解分工

基础讲解稿负责稳定、完整、可复核的教学主线；模型负责结合当前知识状态换一种说法、回答追问和补充新例子；检索负责在需要时找到有出处的定义、公式、接口与延伸阅读。模型可用自身知识补充说明，但须区分来源内结论与扩展说明，不能冒充查证过的资料。检索失败时仍应能阅读基础讲解稿。
