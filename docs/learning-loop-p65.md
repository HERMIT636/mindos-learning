# Learning Loop P6.5：导师教学质量控制

导师先读取真实课程与学习证据、选择原有讲法，再生成结构化回答。新增层在入库前检查深度、近期重复、教学目标和不确定表述；有问题时在原有一次重试预算内改写，仍失败则给出不保存的保守说明。它不评分用户，不改变掌握记录、学习任务或课程位置。

## 工作方式

`原有上下文 → 原有策略 → 同一模型生成 → P6 协议与范围校验 → 质量检查 → 通过后原有记忆管道`

质量控制器是纯函数服务。`evaluate(response, context, strategy, history, message, action, search)` 返回 `approved / adjustments / final_response / quality_flags`。只有通过时才返回可保存的原响应；不通过时返回修复建议，适配层交给 P6 原有循环处理。

- 深度：四档描述回答的展示深度，不是新的能力分数。只读取已有 P0 独立检测证据、实际课程阶段、偏好及 ATIE 深度上限。复杂问题不长篇重讲已独立验证的定义，公式与实现不能突破原有范围。
- 重复：仅查询当前用户、课程、小节与相关知识点最近五次导师回答，不扫描全部历史。检测长回答近似重复及对已验证知识的长篇定义；短回顾、明确复习、换说法、举例、困惑补强和苏格拉底引导保留。
- 目标：长篇明显偏题或旁支不返回当前知识点时要求改写。相关问题可以短答，再联系当前目标；不拒绝用户探索。
- 不确定表述：未知论文、版本或实验细节没有支持时须明确无法确认。实际搜索仍只有标题与短摘要，不可声称读过全文。虚构链接、未经支持的具体数字、作者和阅读全文断言会被拒绝；用户给出的链接允许原样引用，但不会成为事实认证。短摘要支持的原文表述允许保留。

规则是保守的文本与结构检查，能发现部分明显问题，不能完成全面语义理解、识别所有幻觉或证明事实真实；同义改写可能漏检，合法长讲解也可能被误判。通过检查不等于知识认证，模型自信也不等于事实可信。未来提升规则需依照真实失败案例和人工教学评审验证，不扩大自动能力判定。

## 重试与数据边界

初次生成加一次重试，最多两次实际模型调用；格式失败与质量失败共用预算，不再增加质量评审调用。修复提示保留原问题、教学目标、有效知识、策略及必须的内容块。第二次仍不合格时不保存讲解、不写记忆或候选观察，展示保守说明。

`TutorResponseMeta` 是独立内部表，字段包含 `strategy / quality_flags / retry_count / approved / created_at` 和所有权、请求关联。仅保存简短规则代码，不保存无效原始输出、完整请求或模型思考。通过的元数据关联原导师消息，失败元数据只保留代码。每门课最多保留 100 条；开发面板读取最近 20 条。已保存请求的重复提交不重新调用模型，也不重写元数据。

质量控制器不写 TutorMemory，不根据回答重复直接制造学习困难或误区。P6 已有引用确认、候选观察和原有 P0 独立检测路径保持不变。

## 使用与开发面板

普通用户继续使用原悬浮导师，聊天接口仍是 `POST /api/tutor/chat`。窗口、结构化展示、拖动、缩放与刷新恢复保持原行为。

仅服务端设置 `MINDOS_DEBUG_LEARNING=1` 并重启时显示“导师质量记录（开发模式）”。面板只展示策略、`passed/fallback` 与重试次数。内部 `GET /api/tutor/quality-debug?context_id=课程编号` 同时检查服务端开关与课程所有权，普通模式返回 404，客户端参数无法启用。关闭服务端开关并刷新页面即恢复普通界面。

## 验证

根目录与发布目录分别通过 493 项自动测试，其中新增 86 项；12 组浏览器检查与 3 个真实模型场景通过，个人数据库未改变，55 个冻结文件 SHA 与基线一致。两份目录同步检查为 270 个文件、零差异。

实际结果见 [验证报告](validation/learning-loop-p65-validation.json)、[真实模型场景](validation/learning-loop-p65-real-model.json) 与 [接入审计](learning-loop-p65-audit.md)。新测试覆盖检查器、混合格式/质量失败、重试一次、保守回退、真实学习状态不变、隔离、回收站、复制、删除、开发权限与冻结 SHA。

真实调用只读取本机模型配置，使用临时合成课程和原有小测产生的 QKV、矩阵证据。未知论文为刻意虚构的测试名称；没有检索结果可支持其细节。无效输出只留类型代码，合格解析结果用于验证，不保存模型内部思考。有限场景通过不代表一般教学效果或事实正确率。

复现自动测试：`python3 -m unittest discover -s tests -v`。浏览器环境可用时执行 `python3 scripts/check_browser.py tutor_quality tutor_p6 tutor`。真实模型验证需显式提供个人配置库路径和密钥文件路径给 `scripts/check_tutor_quality_model.py`；密钥不会写入报告或公开仓库。

## 11 项最终自审

1. P0–P6 核心算法是否改动：没有，55 文件 SHA 与基线一致。
2. 是否建立第二套知识状态：没有，只读取现有 P0 与 ATIE。
3. AI 是否直接改掌握度：没有，逐表快照与回归验证。
4. 是否保存模型思考：没有，只保存原协议合格内容和简短元数据。
5. 是否最多重试一次：是，复用原 P6 循环，另有第三次调用拒绝保护。
6. 第二次失败是否安全回退：是，保守说明不保存为学习回答。
7. 是否避免重复：有近期与已验证定义检查，明确保留复习及补强；不宣称完整语义去重。
8. 深度是否匹配真实状态：读取独立检测证据与原 ATIE 上限，不把自述或模型置信度当能力。
9. 是否与当前目标对齐：保留原范围检查，并增加明显偏题及长旁支检查。
10. Tutor 是否仍可拖动并恢复：桌面与手机浏览器检查验证。
11. 是否完成自动、浏览器和真实模型验证：实际数字与通过情况记录在验证报告，不以模拟结果代替真实调用。
