# 架构审查问题修复记录

日期：2026-10-01。对应 [原审查报告](architecture-review-2026-10-01.md) 的 F01—F09，以当前源码和临时测试结果为依据。

| 问题 | 实际修复 | 验证 |
| --- | --- | --- |
| F01 同名定义与引用错配 | 定义不同必须明确选择采用新定义或保留旧定义；采用后替换定义及其引用并保存知识历史；保留时不增加新引用、不提升旧定义状态，也不导入被拒绝候选的关系 | 存储测试及浏览器新旧定义对照、选择保留 |
| F02 地址变化沿用旧密钥 | 地址变更且已有密钥时，必须重新输入密钥或明确勾选清除；原地址留空仍可保留密钥，接口不回显密钥 | 临时 API 测试，没有向替代地址发送密钥 |
| F03 教师与助教选材不同 | 共用 `context.course_materials`，上传资料优先，兼顾章节匹配，每次最多四份、每份最多4000字完整原文块；双方使用相同选择规则 | 上传资料后加入五份网页资料，两个入口仍选择同一上传资料 |
| F04 深度协议与补前置冲突 | 统一概念层为 conceptual，兼容旧 concept；概念层禁止公式推导；BACKTRACK 将本次补充的前置知识提升为当前核心，生成和检查使用同一范围 | 高数学偏好仍遵守概念层；长前置解释不再被当成辅助知识拒绝；原教学回归通过 |
| F05 旧响应覆盖当前页面 | 请求绑定页面版本；切课程、切知识点或回首页使旧响应失效，停止后续依赖操作；后台已保存的结果仍归原课程 | 浏览器控制延迟，分别验证章节、课程加载、知识点请求和回首页 |
| F06 课程变化后内容失效不透明 | 增加课程依据版本、章节与原子讲解版本、内容历史；目标、难度、来源偏好、资料、来源冲突和导入知识变化会提示旧讲解需复核；可主动重新生成、查看最近五份旧讲解；生成期间依据变化会拒绝保存 | 编辑后显示旧版提示；重新生成保留旧文、测验和掌握记录；过期生成不写入；浏览器验证可见历史 |
| F07 索引与审查知识混杂、局部地图无法补全 | 明确 planning_index / reviewed_knowledge 角色，显示已审查知识与待核对索引数量；缺失小节可以补全索引，保留已审查原子、引用与编号，新增索引不自动 verified | 局部已审查地图补全后覆盖全部小节，原定义和引用保持；新增节点仍 candidate |
| F08 重开数据库中断活任务 | 删除 Storage 初始化时的全量中断；任务带执行者和心跳，每15秒续期，仅300秒无心跳的任务被恢复为 interrupted；终结任务不会被迟到更新改回 running | 重开存储、新建发现引擎不影响活任务；过期任务可重试；迟到更新不能恢复旧任务 |
| F09 手动搜索拒绝短词 | 与自动发现共用查询规范化，接受 AI、ML、RL、图论，拒绝空白及无意义符号 | 临时 API 对四个短词和三种无效输入的回归测试 |

还增加了课程资料选择服务、内容版本服务和源码同步脚本，减少跨入口重复逻辑；学习状态读取最近测验时按提交时间排序，避免把较晚创建但较早提交的测验误当最新证据。知识导入、聊天、偏好变化、内容再生成均不直接改变掌握率，也不自动推进小节。

## 接口兼容与数据迁移

- `/api/sources/review` 可带 `merge_choices: {"c1":"replace"}` 或 `{"c1":"keep"}`。不同定义缺少选择时返回可读错误，批次仍待审查。相同定义可按原方式增加相容引用。
- `/api/models/save` 新增 `clear_key` 布尔字段。默认 false；地址不变时沿用原行为。
- `/api/sections/lesson`、`/api/atoms/lesson` 支持 `regenerate: true`。默认仍保留第一次成功的讲解。旧讲解及来源依据存入 `content_history`；章节历史通过课程响应 `lesson_history` 返回，知识点历史通过 `content_history` 返回，均限制为最近五份展示。
- Course 新增 `content_revision`，Section 新增 `lesson_revision`，atom_content 新增 `content_revision`。自动迁移不重建课程、知识原子或测验，不推断既有内容是否在修复前已经失效。
- 课程索引与已审查知识继续使用现有图谱容器，增加角色与覆盖状态，避免另造一套关系和学习证据；角色不是新的掌握状态。
- 原课程审查稿仍是创建时的历史方案，修改学习目标不会冒充重新完成课程审查。重新生成按当前目标、难度和资料生成当前小节，章节结构保留。
- 发现任务仍为本机线程任务；300秒租期用于恢复失去响应的任务，不是生产级分布式任务队列。服务崩溃后可在租期过期后重试。

## 实际验证

- 项目根目录与发布目录完整自动化测试各 **117 项通过**：原102项以及15项架构回归。既有“同名定义合并”和“任务初始化恢复”测试按修正后的行为更新，并增加独立回归验证。
- Edge/Playwright **四组浏览器回归通过**：ATIE结构化教学；响应延迟、定义取舍与内容版本；课程管理；课程悬浮助教。涵盖桌面和既有移动视口回归，未发现页面脚本错误。
- 在临时数据库、合成公开资料与测试模型服务中运行，不修改个人课程数据库和密钥。没有进行真实模型综合教学质量、学习效果或多进程压力评估。
- 默认联网入口仍只覆盖指定公开索引，不称为全网搜索；课程审查仅使用标题及摘要；正文生产仍要求可核对原文，verified仍只代表引用有效且用户确认。
- 项目根目录与发布目录使用 `python3 scripts/sync_publish.py` 同步源码；`--check` 检查逐文件内容一致。不复制 data、private、实际环境配置或缓存；不删除发布目录文件、不提交或推送。

原审查中较大范围的服务拆分、统一所有知识点教学入口、追踪与日志治理仍属于后续渐进重构，本次没有将它们包装成已完成。当前保持一个本机可运行的应用。
