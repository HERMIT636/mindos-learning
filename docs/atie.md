# 自适应教学智能引擎（ATIE）

ATIE 先决定怎么教，再由模型生成教学内容。决策服务不调用语言模型、不生成课程正文、不修改知识地图或掌握记录。

本项目采用 Python 服务和原生 JavaScript 前端，新增实现放在 `mindos/adaptive/` 与 `web/components/teaching/`；继续使用原有课程、小节和知识原子，不另建 React 或一套课程系统。

## 运行流程

确认的课程目录、知识地图与原子 → Learning State Manager → ATIE → Teaching Action → 内容生成模型 → 内容块与范围检查 → 保存 → 按类型渲染。

章节首次生成、章节追问及悬浮课程助教都执行这条流程。打开已保存的章节也会计算下一次教学决策；当前历史讲解保留，不自动改写。助教原有规划调用仅判断搜索需要及关联知识点，教学策略统一由 ATIE 决定。

## 学习状态与证据

Learning State 包含当前课程、小节、可选知识原子、课程目标、认知状态、概念／应用／推理／数学题表现、最近小测、既往教学策略、用户反馈、数学基础自报和讲解偏好。

能力未知时 `knowledge_level` 和 `confidence` 保留空值，不填虚构的 0.6。测验正确率也不当作认知置信度。`weak`、`partial_understanding`、`strong` 是基于已有独立小测表现的教学信号，不是独立能力认证。

新小测题带 `assessment_type`，支持 concept、application、reasoning、math。提交后按真实作答统计相应正确率，下一次读取状态即可调整策略。旧题没有标签时归为 unknown，不猜测它测试了哪种能力；题目类型由生成时的标记决定，分类本身也可能需要审查。

“没懂”“公式困惑”等反馈与教学策略单独保存，只影响后续讲法。阅读、聊天、口头自查和资料导入不会新增掌握证据。原有独立小测、知识原子证据与课程推进规则保留。

## 教学动作协议

第一版使用可解释的规则决策。Teaching Action 示例：

```json
{
  "action": "INTRODUCE",
  "goal": "建立Attention与QKV的直觉",
  "depth": "beginner",
  "presentation": ["question", "analogy", "diagram", "concept", "checkpoint"],
  "need_check": true,
  "structure_level": 3,
  "allow_formulas": false,
  "allowed_depth": "detailed",
  "forbidden_topics": ["Encoder"],
  "reason": "先建立直觉与本节学习目标",
  "policy_version": "atie_rules_v1"
}
```

| 动作 | 触发方向 |
| --- | --- |
| INTRODUCE | 首次学习，先建立直觉 |
| EXPLAIN | 常规解释 |
| REPHRASE | 没理解，或要求换说法；结合上一种讲法改用例子、图示 |
| VISUALIZE | 用户需要图示 |
| EXAMPLE | 需要案例，或应用题／最近小测表现薄弱 |
| DEEPEN | 主动深入，或数学基础较高且在本节范围内 |
| SIMPLIFY | 公式困惑，暂缓公式、改用直觉和例子 |
| BACKTRACK | 已测前置知识薄弱，先补基础 |
| CHECK | 口头理解自查 |
| CHALLENGE | 用户请求挑战，仍受本节范围与深度限制 |
| REVIEW | 用户请求复习 |

“EXPLAIN_WITH_ANALOGY”在这里表示 EXPLAIN 动作配合 analogy 表达，不另外添加一个与上述动作重复的枚举。

数学基础较高的自报、足够的数学题表现，或用户主动要求深入，可以允许在当前范围内使用公式。公式困惑、补前置、导引课及后续知识探索优先采用概念解释，不能用高数学基础越过章节范围。

结构等级 0 是简短文字，1 是定义与简单例子，2 是局部教学结构，3 用流程或关系图，4 用符号解释、推导、实例和自查组织数学内容。简单提问不会强制输出完整教学流程。

## 教学内容块

新生成内容返回 `{"blocks":[...]}`，类型支持 text、question、analogy、concept、flow、diagram、comparison、formula、example、checkpoint。正文与标题使用普通文字，图表通过数据表达。

```json
{
  "blocks": [
    {"type": "question", "content": "理解一个词时，为什么不平均参考所有词？"},
    {"type": "analogy", "content": "像查资料，先比较资料标签，再取需要的内容。"},
    {"type": "diagram", "data": {
      "nodes": [{"id":"q","label":"我想找什么"},{"id":"k","label":"信息标签"}],
      "edges": [{"from":"q","to":"k","label":"比较相关程度"}]
    }},
    {"type": "concept", "content": "Attention按照相关程度分配信息权重。"},
    {"type": "checkpoint", "content": "Query与Key分别在做什么？"}
  ]
}
```

模型必须按决策里的 presentation 顺序提供内容；缺失内容块、无效关系节点、过深公式、Markdown文章和明显超纲会触发一次修订，仍不合规则不保存。公式块要求解释符号。图示采用前端绘制的 SVG、流程用步骤列表、对比用表格；模型不能传入可执行图表代码。前端通过 textContent 放入文字，已验证 HTML 字符串不会作为标签执行。

JSON 语法错误（例如流程块漏写闭合括号）也进入同一次修订预算：保留失败原文和解析位置，交给模型修订，再检查内容块与教学范围。语法与内容错误合计最多修订一次；修订仍失败不保存。连接、密钥和截断错误保留原有错误提示，不当作格式错误修订。

“口头自查”允许用户写自己的解释，再请教师看思路，明确标注不计入掌握记录。章节与助教均提供换说法、例子、图示和公式困惑反馈按钮。课程页可设置“我的数学基础”和讲解偏好，设置只影响后续生成。

旧讲义及旧聊天不会被覆盖，前端转换为兼容的文字块展示。知识原子的快／深阅读仍保留原有生成入口和存储结构，展示也使用兼容文字块；本次 ATIE 决策接入范围是章节与课程助教。

## 接口与存储

保留原有章节生成、追问、小测和课程助教接口，响应新增 blocks／lesson_blocks 与 teaching_action。

新增：

- `GET /api/courses/{id}/learning-state?ordinal=1&atom_id=...`：读取已开放小节的状态与知识上下文。
- `PUT /api/courses/{id}/teaching-preferences`：设置 math_level（unknown/basic/advanced）及 preferred_style（visual/example/text/formula）。不能写入正确率、掌握程度或置信度。

章节追问和助教提问可选传 `feedback`，表示用户自己的请求；不接受它作为小测评分。

迁移增加章节、章节对话、助教消息的内容块和决策 JSON，以及 teaching_preferences、teaching_feedback、teaching_actions。教学动作与成功生成的内容在同一事务保存；失败不会留下成功教学动作。反馈可以保留，因为它是用户已经提出的请求。

所有状态按本机会话和课程隔离，未来小节禁止读取。软删除保留记录，恢复后可用；复制课程不复制教学动作、反馈或偏好；永久删除清理相关记录。来源策略、冲突提示、原文引用有效性与知识候选确认规则不变。

## 验证与能力边界

自动化覆盖：初学者策略、换讲法、高数学基础及范围优先、真实作答的能力维度、旧题未知维度、全部动作与结构等级、流程与关系图协议、非法图示与隐藏公式、失败不保存、持久化、回收站／复制／删除、接口隔离及防止伪造评分。

浏览器覆盖：新章节块、图示、口头自查不更新掌握、反馈换讲法、偏好保存与公式、失败小测后的补前置、刷新保留内容块、助教块、安全文字渲染及移动端。同时保留并运行悬浮助教回归测试。

真实 `deepseek-flash` 的四个临时课程场景已得到预期动作与内容块：初学者 INTRODUCE、困惑 REPHRASE、高数学基础 DEEPEN、模拟小测失败后 BACKTRACK。[实际输出与检查结果](validation/atie-2026-10-01.json)供复核；失败小测是测试中模拟提交，不能当作真实用户学习效果。

随后定位到“代数结构与图论”课程的实际格式失败：模型在流程块后漏了一个闭合括号，解析于第 1307 个字符处失败，原实现尚未进入内容检查就退出。已将解析失败接入修订流程，并补充完整嵌套 JSON 示例。重放该条实际失败输出、由真实模型修订一次后通过协议与范围检查；在临时课程中保存成功，掌握测试数保持零。[失败原文及修订结果](validation/atie-json-repair-2026-10-01.json)可供复核。

ATIE 第一版是规则决策，知识薄弱信号依赖已有题目与标记。内容检查验证协议和明显超纲，不是完整语义或事实认证；单课程样例也不证明普遍教学效果。

## 比较表协议与格式兼容

比较表的 `columns` 仅包含值列，每行 `values` 的长度必须相同；行名称由 `label` 单独提供，首列表头可通过 `label_header` 指定（默认“比较方面”）。模型如把“性质”等明确行标签表头放入 `columns`，同时所有行都以 `label` 提供该列且有一致的剩余值列，生成器会将首列表头无损移至 `label_header`，保留原文及所有单元格，在教学验证记录中保存转换信息。

不规则行宽、缺少单元格、未知或冲突的表头不会靠填值通过检查，仍进入一次模型修订；失败后页面显示具体检查原因。结构规范化以后仍执行教学策略顺序、公式限制和小节范围检查。模型原始返回及失败日志保留在本机，不提交私人日志或课程数据。
