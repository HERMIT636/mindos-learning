# 本地原型运行说明

## 学习流程

1. 配置并测试对话模型。默认使用免额外密钥的 Wikipedia 与 GitHub 公开索引；需要更广的网页检索时，可选配 Brave 或 Tavily 搜索 API 地址与密钥。
2. 输入课程名称、可选目标和检索方式。模型拟定 2—3 个搜索词，服务端从所选公开索引读取少量标题、链接和摘要。模型只生成通俗的课程说明、学习成果、知识方向和 4—16 节的简短目录，不生成具体讲义或题目。
3. 学习者审查结果。若范围不对，可修改课程名称、目标，填写修改意见后重新搜索和生成。每版审查稿持久保存为最新状态，刷新后仍可继续。确认最新版后，才创建正式课程；重复确认不会创建副本。
4. 进入第一节，主动生成并保存讲解；可追问。每次小测 4 道单选，提交后保存题目、作答、评分与解释。可复测旧小节；只有主动点击“进入下一小节”才推进。

课程记忆以课程 ID 和浏览器会话隔离。小节状态根据最近两次已提交小测得出：低于 60% 为“需补强”；60%—84% 为“正在掌握”；至少两次且最近两次平均达到 85% 才显示“较稳固”。课程平均正确率只覆盖已测小节，旁边同时显示覆盖率。这些均是复习线索，尚无测评效度验证。

## 搜索与资料边界

默认检索由服务端访问 Wikipedia 与 GitHub 公开索引，无需用户另申请搜索密钥，但只覆盖这两个来源，不能称为全网搜索；索引服务不可用或没有结果时会明确报错。可选的 Brave、Tavily 及兼容 API 提供更广的网页搜索，需单独配置地址与密钥。DeepSeek 等普通 Chat Completions 模型不会自动访问互联网。MindOS 只取每条结果的标题、链接和短摘要，用于形成审查稿，不抓取或存储网页全文。结果及其嵌入内容是未经核实的数据，模型提示词要求忽略其中的指令、不伪造来源，也不声称已阅读全文。用户应点击来源核对重要课程范围。课程搜索词会发送给所选来源；模型与搜索服务可能收费。

## 数据与接口

默认数据库是 `data/mindos-demo.sqlite3`。`search_profiles` 分别保存 Brave/Tavily 地址与加密搜索密钥（兼容旧 `search_settings`），`course_drafts` 保存当前审查稿、版本、搜索来源和免密钥检索状态，确认后才写入 `courses` 与 `sections`。讲解、追问和小测分别存储。旧版数据库首次打开前会在本机创建备份；本机加密主密钥不随数据库自动迁移。

- `GET /api/bootstrap`：本会话的模型、搜索、课程和未确认审查稿。
- `POST /api/search/save`：可选，保存 `provider=brave|tavily`、`api_url` 和加密的 `api_key`。密钥留空保留原值；更换地址需重新填写密钥；`clear=true` 清除所选服务密钥。旧请求未传 provider 时仍使用 Brave。
- `POST /api/courses/draft`：按 `search_mode=public`（默认）、`search_mode=brave` 或 `search_mode=tavily` 检索并生成或修改审查稿。
- `GET /api/draft?draft_id=...`：恢复本会话审查稿。
- `POST /api/courses/confirm`：按预期版本确认并创建课程。
- `GET /api/course?course_id=...&ordinal=...`：读取已开放小节及课程记忆。
- `POST /api/sections/lesson`、`/api/sections/ask`：生成并保存讲解、追问。
- `POST /api/sections/quiz`、`/api/quizzes/submit`：生成、提交并评分。
- `POST /api/sections/advance`：用户显式推进一节。

所有课程和审查稿接口按浏览器会话筛选。没有正式账号或多人权限系统，不适合公网或正式学生数据。模型可能编造课程顺序或题目答案；正式试点需要教师审核、独立测评和效度检验。

## 免密钥入口的检索策略

- 模型首先拟定简短的学科主题，避免把“入门、课程、大纲、教程”等泛词堆在一起；中文词优先用于中文 Wikipedia，英文词优先用于英文 Wikipedia 与 GitHub。没有英文词时使用现有词，不擅自伪造翻译。
- 同时检索三个来源；每个来源先查一个词，没有可用结果时再尝试课程名称或另一个已有词。每个来源至多两次请求，单次请求超时参数为 6 秒；拒绝访问、限流或连接失败时不反复重试该来源。
- GitHub 扩展到仓库名称、描述和 README 的索引匹配，但只读取仓库返回的标题、链接和简短描述，不下载 README 或网页全文。接口依据 [GitHub 搜索文档](https://docs.github.com/en/search-github/searching-on-github/searching-for-repositories) 与 [MediaWiki 搜索文档](https://www.mediawiki.org/wiki/API:Search)。
- GitHub 结果需在标题或简短描述中命中至少一个搜索关键词，避免仅在 README 深处匹配的无关仓库挤占结果；此规则也可能漏掉相关资料。交替选取各来源结果并去重，总计至多 8 条。保留搜索词、各来源结果数、空结果或不可用原因，写入 `search_report_json`，审查页刷新后仍展示。来源计数是筛选合并前的可用条数。
- 部分来源失败时使用剩余真实结果并提示；全部无结果时明确报错，不生成带虚构来源的审查稿。未扩展为全网搜索，非编程课程的资料覆盖仍可能有限。

## 课程知识地图与两种模式

这次按课程组织知识结构：课程 → 小节（章节教学单位）→ 知识原子；每门课保存独立图谱。知识定义与学习状态分别处理：图谱描述知识点，学习事件和已提交题目提供用户状态证据。相同名称不自动合并，不会把课程 A 的记录带到课程 B。

- **章节讲解**：连续系统地学，默认从零讲透当前小节。已有地图时，把本节原子、此前原子证据传给模型；追问也参考当前课程的状态。
- **知识原子**：查看定义、用途、类型、深度、前置和关联知识；按需快速复习或深入讲解、追问、定点小测。不是另一套必须重学的课程。已看章节可直接测对应原子。
- **知识地图**：SVG 前置关系视图与按章节的原子列表，可键盘操作；AI 关系未经教师核验。只能通过章节“进入下一小节”推进；地图不解锁未来教学。
- **学习进度**：用户明确标记章节已读，或原子已阅读/复习后留下事件；生成讲解不自动等于已阅读。阅读或追问不产生测试正确率。
- **掌握线索**：题目明确关联原子，提交后累计题目证据；取该原子最近两次测试中相关题目的加权正确率。少于两次测试不能标为“较稳固”。未测显示空状态而非零分；总体同时展示已测覆盖数。未关联的历史题仍保留章节成绩，但不凭空分摊到原子。
- **建议学习**：优先处理最近测试低于 60% 的原子，再提醒距上次活动至少三天的原子、已读未测原子和尚未阅读原子。建议顺序不改变章节顺序。
- **基础摸底**：可跳过，仅检查第一节原子；保存为独立诊断证据，不算章节综合测试，不自动跳过章节。

本次未实现自动跨课程掌握迁移、项目实操评分或多维能力认证；单选题不证明实践或迁移能力。图谱、教学、题目质量仍需要真实模型试点和教师核验。

### 存储与接口

新增 `course_graphs` 保存课程结构快照，`atom_content` 保存快速/深入讲解，`atom_turns` 保存追问，`learning_events` 保存阅读与复习事件。`quizzes` 增加 `scope` 和 `target_atom_id`，旧记录默认为章节测试；题目 JSON 的 `atom_ids` 提供精确关联。不会删除旧课程、讲解或成绩。

- `POST /api/knowledge/build`：按需生成地图；已有图谱直接复用，不覆盖学习历史。校验编号、章节覆盖、单节原子数量、引用范围和前置循环。
- `GET /api/knowledge?course_id=...`：当前课程图谱、证据覆盖及建议。
- `GET /api/atom?course_id=...&atom_id=...`：已开放原子的内容、对话与测验。
- `POST /api/sections/read`：记录本节已读；该节的关联原子共享阅读记录。
- `POST /api/atoms/lesson`：`mode=quick|deep`；按需生成并保存。
- `POST /api/atoms/ask`、`/api/atoms/read`、`/api/atoms/quiz`：原子追问、阅读记录与测试。
- `POST /api/knowledge/diagnostic`：第一节基础摸底。
- `POST /api/quizzes/submit`：所有已生成测验的统一提交入口，禁止跨课程提交和重复提交；提交前不返回正确答案。

### 验证

运行 `python3 -m unittest discover -s tests -v`。测试覆盖图谱引用与循环、旧数据迁移、未标记题目不虚构原子成绩、两种模式共享记录、课程/会话隔离、待答题不泄露答案、未来原子不能提前学习，以及原课程与搜索流程。

浏览器验证使用临时数据和模拟模型：先运行 `python3 tests/browser_fixture.py`，根据输出设置 `MINDOS_TEST_URL` 与 `MINDOS_TEST_COOKIE`，再运行 `node tests/browser_knowledge.cjs`。需要已安装 Playwright 和 Edge；可用 `PLAYWRIGHT_MODULE` 指定已有 Playwright 模块路径。测试地图生成、章节阅读、原子测试与追问、刷新恢复、390 像素手机布局和返回章节。结束后 Ctrl+C 关闭模拟服务。模拟测试不能证明真实模型教学质量。

## 资料驱动的知识生产

进入课程展开“资料与知识生产”，可导入五类文件、文字或公开网页正文。选择完整的结构块，模型生成带原文引用的知识候选；用户确认且引用检查通过后才进入课程地图。图谱索引与经过资料审查的知识分别标明来源；不把导入、阅读和追问当作掌握证据。完整架构、API、解析限制、测试方法见 [知识生产说明](knowledge-production.md)。

课程创建现在支持当前水平和可选资料；确认后自动进行知识缺口发现。发现状态、正文失败原因及来源冲突可在课程中查看；知识候选仍须单独审查。详情见 [课程来源偏好与自动发现](source-policy.md)。
