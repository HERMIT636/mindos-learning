# GPU 异构执行与数据传输

这是从零开始的 MindOS 课程草稿，尚待教师审核。读不懂某个词时，先看下面的术语，再按步骤阅读；无需先会做题。

## 第 0 步：先认清本讲的词

- **GPU**：适合大量相似计算同时执行的加速器。
- **核函数**：在设备上并行运行的计算代码。
- **数据传输**：主机与设备之间移动输入或输出。

## 第 1 步：从一个问题出发

GPU 并行度很高，但内核启动与主机设备数据搬运有开销。小任务可能因传输成本而不划算；算子赛更需要分清主机侧调度与设备侧真正计算。

## 第 2 步：理解它怎样工作

主机准备输入并发起设备工作；设备核函数用大量并行执行单元处理数据。不同存储层级具有不同容量与访问成本，数据复用和连续访问影响吞吐。比较方案时要明确计时范围包括内核、传输还是端到端。GPU 编程模型的概念可迁移，但具体 API、内存层级与同步语义不能直接跨厂商照搬。

## 第 3 步：跟着例子做

对一百万个元素逐项加法，设备可并行计算；但如果每次只传 8 个元素、启动一次内核，启动与搬运可能超过计算时间。可以适当批处理，先保证结果与 CPU 参考实现一致，再测规模变化下的端到端耗时和纯内核耗时。

### 1. 拆开总耗时

要比较 GPU 与 CPU，先把“传入数据、GPU 计算、取回结果”三段时间加起来。若传输要 8 毫秒、计算要 1 毫秒，总计至少约 9 毫秒。

### 2. 再看任务规模

如果 CPU 只用 3 毫秒完成同一小任务，GPU 的计算虽然快却没有整体收益。输入更大或数据可以留在设备上重复使用时，结论可能反过来。

## 常见误区与自查

不要把异步发起时间误当作核函数完成时间，也不要把 CUDA 的接口名称直接当作 Ascend C 的接口。自查执行设备、数据所在位置、同步点与传输次数。
