# 教学编排器

课程讲解按“确认课程目录 → 当前小节 → 教学范围 → 模型讲解 → 内容检查 → 保存”执行。当前页面布局和进入下一小节的操作保持原样。

目前章节与课程助教已接入 [ATIE](atie.md)：教学编排器提供本节范围，ATIE 决定讲解方式，再生成并检查结构化教学内容块。下文保留范围控制与最初模型验证的说明。

## 教学范围

现有 `sections` 就是本项目的 Lesson，不再另建一套课程进度模型。每节新增：

| 字段 | 含义 |
| --- | --- |
| purpose | 本节教学目的 |
| core_atoms | 当前核心知识，可详细讲解，Level 3 |
| related_atoms | 辅助理解的知识，只简短介绍，Level 1 |
| future_atoms | 后续知识，不主动展开，Level 0 |
| difficulty | beginner / basic / intermediate / advanced |
| teaching_depth | introductory / conceptual / detailed |

课程审查时要求模型生成这些元数据；旧课程和未返回元数据的模型仍可使用。旧表自动补字段，教学目的继承小节目标，导引类标题使用 introductory；缺少知识原子时按小节标题和目录划定范围。已有讲义不被覆盖。

`mindos/teaching.py` 中的 `TeachingOrchestrator` 结合当前目录、各节元数据及已有知识地图，将本节原子作为核心，将较早小节中通过 prerequisite 边指向当前原子的知识作为辅助，把较晚小节知识作为后续范围。被明确允许简短介绍的知识保留 Level 1。不会为生成教学范围而自动建立知识地图或导入知识候选。

例如 Transformer 导引课核心是背景与序列问题，可简短提及 Attention，QKV 计算、多头注意力和 Encoder 细节留到对应小节。进入 Attention 小节后，该节核心知识可以详细解释。追问和悬浮课程助教也收到教学范围；用户主动询问后续内容时，先标明阶段并解释直觉，详细计算留待相应小节。“继续”不会推进课程。

## 内容检查与重写

`ContentValidator` 检测明显超纲信号：后续或辅助知识段落中的公式、步骤、实现代码和部分结构细节，以及导引课中的多行公式或代码。单纯提到后续名称或说明稍后学习不算超纲。

检测到问题后只重写一次，再执行相同检查。仍未通过时返回可理解的错误，不保存讲义或部分教学历史。通过后将检查结果随讲义保存。初稿、重写稿及检查结果使用现有本机诊断日志记录；模型密钥继续隐藏。

**能力边界：**目前检查基于规则，只用于发现明显超纲，不是完整语义理解、难度评估或事实认证；隐含超纲仍可能漏检，局部规则也可能误判。需要结合真实模型输出和用户反馈继续完善。

## 接口和记录

`GET /api/lessons/{lesson_id}/teaching-context` 返回本节目的、难度、三组知识名称、展开等级、完整目录和已有教学记录摘要。lesson_id 使用原有 section ID；只允许读取本浏览器会话拥有、未删除课程中已开放的小节。接口不调用模型，也不修改课程或掌握记录。

原有 `POST /api/sections/lesson` 自动走编排和检查，不要求前端先额外请求上下文。`POST /api/sections/ask` 及课程助教也使用同一范围。

`lesson_teaching_records` 保存 user_id（当前本机会话标识）、course_id、lesson_id、covered_atoms、created_time，以及当次教学上下文和检查结果。covered_atoms 只记录讲义实际提及的核心知识名称，表示已生成讲解，不表示用户已阅读或掌握。首个成功讲义与记录在同一事务保存；重复请求不会覆盖原讲义或增加重复记录。

软删除保留记录，恢复课程后仍可读取；复制课程保留教学元数据，不复制教学记录或讲义；永久删除清理相关记录。知识原子结构、正式图谱审核规则及独立测试更新掌握程度的规则不变。

## 验证

`python3 -m unittest discover -s tests -v`

`tests/test_teaching.py` 覆盖无图谱范围、原子前置关系、当前／未来范围转换、访问隔离、明显超纲与简短提及、单次重写、失败不保存、旧表迁移、复制／回收站／永久删除、提示词及原有生成接口。按 requirements.txt 安装依赖后运行完整测试。

### 2026-10-01 真实模型检查

使用本机已保存的 `deepseek-flash` 配置，在独立临时数据库中检查 Transformer 课程。个人课程数据库仅只读读取配置，密钥未回显，测试输出不含模型凭据。

首次检查发现：规则把“前馈网络、残差连接”等名称的简短列举误当成结构细讲。现已修正：名称列举及前置知识的简短介绍可以通过；详细计算、结构操作和公式仍会被检查。增加了对应的真实输出片段回归用例。

修正后重新请求模型，实际结果如下：

| 场景 | 观察到的模型输出 | 流程结果 |
| --- | --- | --- |
| 课程导引与预备知识 | 2194 字符，讲背景、RNN 局限和学习路线；后续知识只提名称，无 QKV 公式或完整模型结构讲解 | 首稿通过，无重写 |
| 导引课主动问“Attention具体怎么算？” | 987 字符，说明这是下一节内容，用直觉解释并简述 Q/K/V 的角色，计算留到下一节 | 正常回答，不自动推进 |
| 明确推进后学习 Attention | 3049 字符，展开 Q/K/V 变换、匹配、softmax、缩放和加权汇总；Multi-head Attention 与 Encoder 留待下一节 | 首稿通过，无重写 |

测试课程未增加独立测试证据；小节从 1 到 2 的推进由测试显式执行，非模型自动推进。[完整实际输出和检查结果](validation/teaching-orchestrator-2026-10-01.json)保留供复核。

上述只是单门课程的样例验证，不证明所有模型和课程都能保持范围，也不认证讲解中的全部事实或教学效果。
