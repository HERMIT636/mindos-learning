# Learning Loop P3：个人知识档案与跨课程基础确认

P3 保留课程独立的知识星图和掌握状态，在其上增加用户自己的语义身份、可审查关联、长期知识档案与教学先验。历史基础不是新课程掌握证明，关联确认也不是知识事实认证。

## 使用入口

导航中的「个人知识档案」可按名称、领域和状态查找，展开查看来源课程、答题记录、已测维度与最近验证日期。课程内点击知识星辰，详情显示关联审查和相关历史基础。可确认、拒绝或取消关联；上下位和仅相关概念不会作为同一知识继承。

有相关历史基础时，可选择「快速确认已有基础」，也可正常学习。短测沿用原有诊断出题、答题、证据与评分接口。通过后，ATIE 可以简短回顾相关基础；失败、使用提示或复用旧题都不会当作已独立验证。章节始终由用户主动推进。

## 数据与协作

- `canonical.py`：用户所属的语义身份与映射。按名称、注册别名、领域、类型及摘要召回最多三个候选；比较定义、目标、邻接关系和章节上下文。模型必须通过 JSON schema、关系一致性和有限数值校验，最多一次修复；失败走保守规则。
- 自动确认必须同时满足强名称／别名、领域与类型一致、跨课程上下文一致、same、无冲突和高置信度。目标课程自己的上下文不能作为跨课程证明。模型置信度高但上下文不足，仍保留候选。不能只凭同名合并。
- 新概念可建立自己的身份；该自身份确认不表示已经确认与任何旧课程相同。一个用户／课程／原子最多一个 verified 关联，SQLite 部分唯一索引强制保证。变更保存历史；显式合并保留重定向，拆分和撤销保留课程真实状态。
- `personal.py`：批量读取已确认映射、课程原子和真实状态，按来源状态版本、关联、P2 校准与日期缓存派生画像。单门课程的贡献归一化并封顶，重复原子不增加可信度；独立课程多样性可增加支持。跨课程表现冲突单独标记。未测维度保持未知。
- P2 校准复用原有增量游标，仅刷新有新证据或预测的课程。证据充分的独立选择题高估分类仅降低长期画像信任，不改变课程 mastery、权重、阈值或画像 mastery estimate；模型开放评分不冒充独立校准。样本不足不惩罚。
- `InheritedKnowledgePrior` 排除目标课程自身，保存来源快照与适用深度。来源改变后创建新快照并使旧快照失效；目标语义上下文改变则停用旧关联先验，重新扫描前不重建该先验；更深目标不能自动继承高级应用、实现或迁移能力。较旧历史或低保持率限制先验强度。
- `cross_course.py`：短测沿用 `LearningLoopService.assessment` 与 `Storage.submit_quiz`，产生本课程 `diagnostic_test` 证据，服务器附加 `cross_course_verification`、`inherited_prior_id` 和 `canonical_atom_id`。先验创建本身不追加证据。诊断仍遵循 weighted-evidence-v1，P2 后续时间窗口和独立性规则保持不变。
- ATIE、Tutor 和规划只接收当前主题相关的少量历史摘要。ATIE 只在当前课程实际独立验证后简短回顾基础，不跳章节、不把历史分数填入当前认知状态。课程规划仍保持完整章节。

## 索引与性能

保存索引、补齐索引、资料导入和复制课程后自动执行保守关联扫描。图谱本身上限沿用现有 96 原子；召回 top-3，每次模型扫描最多八个比较任务，每个最多一次修复。课程索引接口返回前只需保存可用索引；可选模型细化在后台运行，最多两个后台任务，失败记录类型并可在详情重试。未完成的关联不妨碍进入课程。

普通驾驶舱／LearningState 读取不写画像缓存；内容生成前和知识详情／档案入口刷新相关快照。画像读取按用户批量联表、聚合证据，避免按每个 canonical 发起独立状态查询。没有新增向量库、全局图数据库或跨用户能力共享。

## 生命周期与边界

软删除课程保留历史，并标记来源已移入回收站；永久删除移除该课程映射、验证快照及依赖，再按剩余来源重建。复制只复制课程结构和资料，重新扫描身份，不复制答题、掌握或验证结果。

本地会话继续作为用户归属边界；这不是生产多用户账户认证。普通接口不暴露画像精确分数和内部 mapping confidence；`MINDOS_DEBUG_LEARNING=1` 才开放个人画像、身份、关联历史和先验开发记录。模型密钥及搜索密钥的现有保护方式保持不变。

## 接口

|入口|作用|
|---|---|
|GET `/api/knowledge/profile?search=&domain=&status=`|个人知识档案，通俗状态与来源|
|GET `/api/knowledge/profile/{canonical_id}`|身份详情；合并后沿重定向读取|
|GET `/api/courses/{id}/knowledge/mappings`|课程关联状态与关系类型|
|POST `/api/courses/{id}/knowledge/mappings/scan`|有上限的语义扫描|
|POST `/api/courses/{id}/knowledge/mappings/{mapping_id}/verify`|用户确认同一概念|
|POST `/api/courses/{id}/knowledge/mappings/{mapping_id}/reject`|拒绝／撤销关联|
|POST `/api/courses/{id}/knowledge/mappings/{mapping_id}/split`|原子拆出独立身份|
|POST `/api/knowledge/canonical/merge`|`source_id/target_id/confirm:true`，显式合并|
|GET `/api/courses/{id}/knowledge/priors`|教学先验及已有验证题目|
|POST `/api/courses/{id}/knowledge/priors/{prior_id}/verify`|启动／恢复本课程短诊断|
|GET `/api/debug/learning/personal`|环境开关限定的内部审查记录|

课程创建继续复用原有审查与确认流程。关联操作请求不接受客户端评分、置信度或掌握状态。

## 验证结果与局限

验证记录见 `validation/learning-loop-p3-2026-10-02.json`，模型结果见 `validation/learning-loop-p3-real-2026-10-02.json`。真实模型只接收合成概念；本地数据库只以只读方式获取加密模型配置，未发送真实学习记录。

same / different / broader / narrower / related 合成例子的模型关系符合预期。信息不足的 ambiguous 例子中，模型给出 same 和 0.97，不能把这当作正确身份结论；程序上下文门槛阻止自动确认，另有自动化回归覆盖这一保护。这些例子只证明结构和保守门槛可以运行，不能证明知识本体绝对正确，也不是大规模语义评测或真实学习者效果证明。

新增 policy 参数是工程启发式，未经真实学习者实验标定。保守领域识别与别名表覆盖有限；无法确定的跨领域／新别名会保留候选，用户仍可审查。后续需用公开语义基准与真实学习者试点评估误合并、漏匹配和教学收益。

## 最终 16 项自审

|问题|结论与证据|
|---|---|
|1. 历史 mastery 直接复制到新课程？|没有。先验／画像模块不写 knowledge_states；复制和新课程测试保持 unknown，阅读记录不当成掌握。|
|2. candidate mapping 用于正式 Profile？|没有。画像输入限定 verified，候选审查前没有历史先验。|
|3. LLM 判断未校验直接生效？|没有。schema、数值、关系与上下文门槛共同校验；错误最多修复一次后回退。|
|4. 同名不同领域隔离？|已测试机器学习 Attention 与认知心理 Attention 分开身份。|
|5. broader / narrower 错误合并？|没有自动合并；同义确认接口也拒绝这些关系，related 同样不能继承。|
|6. 撤销后重建？|画像重建并使相关先验失效；保留历史课程和新课程真实答题状态。|
|7. Prior 写入 LearningEvidence？|没有。测试比较先验创建前后证据数量与状态。|
|8. 快速验证产生 P0 Evidence？|是。HTTP 与浏览器真实提交走原有接口，元数据标识来源，证据类型 diagnostic_test。|
|9. 验证失败篡改旧状态？|不会。旧课程状态逐行不变，当前课程诊断与画像冲突单独处理。|
|10. P2 校准只影响 Profile 信任？|是。冻结 Analyzer 与 policy；新 outcome_type 复用已有规则。高估不改 mastery estimate。|
|11. ATIE／Tutor 只读相关上下文？|是。按当前原子 ID 筛选，最多六个先验；规划按题名／目标相关概念筛选。|
|12. 手动章节推进？|保持。验证前后 current_ordinal 不变，现有推进接口未修改。|
|13. 课程级星图？|保持。跨课程来源仅在原子详情和档案列表，没有全局连线。|
|14. P0／P1／P2 回归？|全量结果与浏览器结果记录在验证 JSON；既有冻结文件逐字节比较。|
|15. 真模型至少 same/different/broader/narrower/ambiguous？|已执行，另含 related；保留模型输出与 ambiguous 高置信度错误，未隐藏局限。|
|16. 映射可运行不等于本体正确？|明确保留此边界，并在模型验证记录中重复说明。|
