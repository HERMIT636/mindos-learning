# 学习闭环核心优化（P0，2026-10-02）

本次在现有课程、知识原子、课程图谱、小测与 ATIE 上连接学习闭环，不替换课程系统，不引入第二套图谱或前端框架。修改前的检查见 [代码审计](learning-loop-audit.md)。

## 用户可以怎样使用

1. 在章节或知识点的小测中独立作答，可选填写“不确定／比较确定／非常确定”。查看解释或在未交卷期间向导师求助，会记录为有提示练习；网页无法把这个记录改回无提示。
2. 课程页增加“下一步学习建议”。同一种混淆反复出现时，提供短时补强；前置知识确有薄弱答题证据时，先检查该前置知识。没有前置证据时先建议诊断，不把“没测过”解释为“不会”。
3. 短时补强为“短诊断 → 必要时一个讲解与案例 → 再检测”。成功后恢复原课程、小节、知识点、快速／深入模式与阅读位置。可以选择先返回原小节；暂缓后不会在刷新时恢复旧检测。
4. 首页显示今天需要复习的知识点。先做回忆检测，独立延迟回忆结果再影响记忆稳定性和复习间隔。即时重复、查看答案后的作答不算新的独立延迟回忆。
5. 离开课程至少七天再进入时，检查最多四个已开放的关键知识点。已经完成的目标不会重复检测；刷新继续原任务。检测完成后建议继续、复习或补强，也可明确选择先回看当前小节。
6. 知识点详情可以展开检测依据，查看理解、应用、迁移、延迟记忆、近期答题记录与建议原因。未测维度显示“未测”，不是零分。星图有对应文字和符号，不只通过颜色区分状态。

没有课程知识索引的既有课程保留章节学习与成绩；按现有入口生成知识索引后，原子层的诊断、补强与解释才有明确目标。不把未关联的历史分数分摊给新原子。

章节仍由用户明确点击推进；补强、复习、恢复检测和导师都不会自动解锁后续小节。旧小节正确率与进度保持原含义，不能当作新知识状态的充分证明。

## 协作关系与数据

```
现有小测的服务器评分
    → LearningEvidence
    → MisconceptionEngine / KnowledgeStateEngine
    → 已存知识状态 + 请求时的时间投影
    → LearningDecisionEngine
    → 补强 / 复习 / 返回检测
    → 新答题证据
```

- `mindos/learning/evidence.py`：统一证据及增量迁移。关联用户会话、课程、小节与原子，保存类型、来源、结果、答题信心、难度、提示、用时、错因和元信息。事件键防止重复写入。客户端提供的信心和用时仅是作答属性，分数仍由服务器计算。第一版题目难度默认 standard。
- `state.py`：唯一多维状态写入点。状态与旧分数都来自实际已提交答案；评分、证据、状态版本、历史和事件同一事务提交。状态读取使用已存结果，不每次调用模型或回算全部证据。
- `misconception.py`：选择题优先用受校验的错误选项映射，无需额外模型调用；开放回答仅产生候选。章节口头自查能唯一对应当前原子时，回答保存后执行候选分析；无法明确归属时不猜测原子或分摊结果。AI 必须引用实际回答，JSON Schema 不通过可修订一次，仍失败则跳过诊断，不中断其他测验。
- `decision.py`：复用课程图谱的 prerequisite 边，方向为“前置 → 后继”。限制遍历深度，防止环路和无限补救。每项建议包含 action、reason_code、priority、目标和元信息。
- `service.py`：课程所有权、已开放知识点、检测目的及任务状态统一校验。修复、返回任务按用户与课程隔离；并发请求重新检查已有任务和待答题，模型调用期间任务已暂缓则不写入。模型不可用时只可复用同课程已校验且有原子标记的历史题；没有题源时说明暂不可用，允许返回课程。
- ATIE 读取新知识状态及闭环上下文，继续负责讲法、难度与展示。微型补强经现有 ContentGenerator、ModelGateway、展示检查和小节范围检查，只围绕一个目标生成内容。模型与修订都失败时回顾现有知识索引，明确标识回退；不会保存不合格模型内容。

新表为 `learning_evidence`、`knowledge_states`、`learning_misconceptions`、`knowledge_state_history`、`loop_events`、`repair_sessions`、`returning_sessions`、`loop_activity` 与迁移标记。复用 quizzes，追加检测目的、提示／信心／用时与任务编号。软删除保留这些记录，结构复制不复制这些记录，永久删除按原确认流程清理新表。

## 规则、未知与边界

所有初始权重、阈值与时间参数集中在 `mindos/learning/learning_policy.json`，版本为 weighted-evidence-v1。这是可以检查和调整的规则模型，尚未经过真实学习者测评效度验证。

- 概念题 → 理解；应用／计算／推理题 → 应用；陌生情境的专门题 → 迁移；至少隔二十四小时的无提示复习 → 延迟记忆。即时重复不会延长稳定间隔。
- 正确率与系统置信度分开。权重、有效证据量和维度覆盖参与置信度；一次答对不能确认掌握。当前“多次检测较稳定”要求四个维度都有结果、均达到阈值，并有足够证据和置信度。
- 聊天、阅读、口头自查以及“我懂了”默认不增加掌握度或数值置信度；它们可记录接触、反馈与课程活动，不推迟独立回忆的时间依据。有提示或复用题的练习降低权重。
- 同一种错因至少在两个不同的、无提示、高自报信心检测中出现，才是规则支持的确认。AI 候选始终只是 suspected；两次不同检测中的定点正确作答可将误区从 weakening 转为 resolved。这也不是独立事实认证。
- 用指数衰减计算 effective_mastery、effective_retention 和 forgetting_risk，只用于当前时间的复习建议，不扣改长期状态或历史成绩。没有独立延迟记忆时，有效记忆值明确为估计。
- 初始复习间隔为 1／3／7／14／30 天，无提示延迟检测成功才增长，失败缩短；每日建议上限二十分钟。补强最多追溯三层，同一原目标与补强目标最多三次、冷却三十分钟。
- 历史已提交题按实际 atom_ids 和 assessment_type 回放一次。缺少原子关联的题保留原成绩及未关联证据，不分摊到小节所有原子；缺少维度标签不伪造理解、迁移或记忆结果。旧“最近两次正确率”保留兼容，新星图不据此直接点亮为已掌握。
- 原子／来源 candidate、verified、deprecated 与引用规则不变。知识生产或导入本身不产生用户掌握证明。相同名称仍按课程隔离。

本次不扩展课程终局报告、跨课程复用、项目评估和独立迁移测验页面。协议保留 transfer_test / project_evidence，未有相关真实证据时仍显示未测。

## 接口

所有入口需要当前本机会话拥有课程。

| 方法与路径 | 作用 |
| --- | --- |
| GET `/api/courses/{id}/loop` | 批量状态、学习建议、复习列表、进行中的任务与待答题 |
| GET `/api/courses/{id}/loop/state?atom_id=...` | 状态、检测依据、误区与解释 |
| POST `/api/courses/{id}/loop/enter` | 进入课程，必要时启动／恢复长期离开检测 |
| POST `/api/courses/{id}/loop/repair-start` | 根据服务器建议启动短时补强，保存返回上下文 |
| POST `/api/courses/{id}/loop/assessment` | review／diagnostic／remediation／returning 的短检测；协议也支持 transfer／lesson_check |
| POST `/api/courses/{id}/loop/repair-content` | 一个目标的微型讲解或明确回退的索引回顾 |
| GET `/api/courses/{id}/loop/repair?id=...` | 查询补强结果与返回位置 |
| GET `/api/courses/{id}/loop/returning?id=...` | 查询恢复检测结果 |
| POST `/api/courses/{id}/loop/hint` | 保存提示使用后返回解释 |
| POST `/api/courses/{id}/loop/defer` | 明确暂缓并保留历史 |
| POST `/api/courses/{id}/loop/self-explanation` | 开放回答的候选诊断，不改变掌握度 |
| POST `/api/quizzes/submit` | 原评分接口，追加可选 confidence / hint_used / response_time_ms 数组 |

禁止通过这些接口提交 mastery、understanding、application、transfer、retention、score 或 state。

开发时可设置 `MINDOS_DEBUG_LEARNING=1`，课程页显示“开发：查看学习证据”；`GET /loop/debug` 返回当前课程近期证据与状态历史，不含密钥。默认关闭。模型原始输出和校验失败沿用本机私有诊断日志，不提交个人日志到公开仓库。

## 升级和验证

更新依赖后重启服务：

```bash
python3 -m pip install -r requirements.txt
python3 -m mindos.server
```

启动沿用 SQLite 增量迁移。建议升级前保留自己的数据库备份。实现和测试未改写个人学习数据库；真实模型检查只读取已有模型配置，使用临时合成课程。

```bash
python3 -m unittest discover -s tests -v
```

验证结果见 [本次验证记录](validation/learning-loop-2026-10-02.json)。浏览器使用临时数据库与模拟模型，真实模型检查另存[受控输出](validation/learning-loop-real-2026-10-02.json)。这些验证证明接口和闭环运行，不等于真实学习成效或题目事实质量认证。
