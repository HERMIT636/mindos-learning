# Learning Loop P2：开放能力检测与状态校准

在课程掌握报告底部进入“进一步验证真实能力”。可选择已开放、未弃用的知识点，做开放解释、辨析错误、应用设计或开放迁移；任务预计 3–10 分钟，可跳过。草稿自动存到本机数据库，刷新后恢复；提交后保存回答与逐项评分引用，重复请求不会重复评分。保存后可离开页面，下次继续。

## 评分边界

- 任务与 rubric 必须通过 JSON Schema、目标、类型、难度、权重和去重检查。失败修订一次，仍失败时明确没有可用题目。
- 评分项必须与 rubric 一一对应；引用必须是用户实际回答的原文，不能引用题目冒充作答。失败修订一次，仍失败时分数为 `null`、回答保留，不按零分或通过处理。
- 程序按 rubric 权重重新计算总分，不接受模型直接给出的总分作为最终分数。模型信心达到校准配置要求且未使用提示，才可形成有效影子观察。
- `project_evidence` 继续权重为零，metadata 保存 `shadow`、任务类型、评分来源和独立性。开放题不调用 KnowledgeStateEngine；不会修改正式 transfer、掌握值、状态版本、历史或 P1 报告散列。
- 模型提出的误解只保存为评估候选，不自动确认，也不改变 P1 报告中的误解状态。
- 在开放任务中向导师求助会先写入不可撤销的提示标记。默认引导思考，用户明确要求时可给答案；该次回答按练习处理，不用于校准。聊天独立保存，不产生状态更新信号。
- 评分与现有状态差距较大时，只提供主动重新独立检测入口，不自动降分、跳转或推进章节。

## 陌生性与多样性

沿用 P1 Unicode、数字／变量归一化、文本相似度与 n-gram 防护，比较课程讲解、历史选择题、终局题和开放任务。任务还声明原领域、目标领域、共同原理、表面差异、陌生性理由和结构。目标领域不得与声明的原领域或已有课程领域完全相同；课程正文中已出现的相同领域标签也拒绝。

任务签名包含类型、目标领域、原子和结构；相同原子的同类型映射结构另行去重，换领域不能规避。同一课程范围内检查历史记录，模型只得到最近的避重复题目文本，不获得完整作答历史。

这些属于文本与声明结构检查，不能证明语义陌生、题目事实正确或评分有效，需要真实学习者验证。第一版不执行用户代码，不是在线编程判题平台。

## 预测与校准

沿用 `learning_prediction_snapshots` 和 `learning_prediction_outcomes`。普通小测创建及开放任务开始时保存原子级预测，P1 原有课程预测保留。扩展结果类型与 `outcome_score`、时间差、评分来源、独立性和证据游标。P1 原有 `score/total` 保留选择题计数；影子结果该计数为 0/0（未评分的选择题），仅 `outcome_score` 承载开放评分，不展示为零分。

预测时间必须早于结果，证据游标也必须前进。修正了旧 P1 关联仅检查游标、未检查时间的问题；未调整任何知识策略权重或掌握阈值。P1 报告策略与知识状态策略不同：按保存的真实 `state_policy_version` 分组，不能把 `course-final-v1` 当知识模型版本。

1／7／14／30 天窗口采用 ±30% 容差，选择最近独立结果。提示、复用、历史导入和同一知识点 24 小时内紧接前次小测的即时重复不进入正式窗口。一个结果可验证不同时间窗口；同一窗口内按结果与原子去重，避免一份结果关联许多预测而虚增样本数。模型辅助开放评分与独立选择题分开统计，不混同证据可信度。

独立选择题记录 Bernoulli Brier（成组题按成功比例展开正确／错误损失，不能把平均分当单个二元答案）；开放模型评分仅记录分数均方差，不冒充二元 Brier。记录分桶加权绝对误差（ECE）、各掌握区间后续成功率。confidence 代表依据充分程度，不是成功概率：单独按信心区间分析掌握预测误差，不把 confidence 直接当 mastery 计算 Brier。课程原子统计按 P1 的 criticality 权重汇总，同一试验有原子级记录时优先采用原子级记录，避免再加一次课程汇总。策略汇总仅统计当前用户的课程，不合并知识点或继承掌握值。

少于 20 次有效样本不判断策略高估／低估；每桶少于 5 次也标为不足。单次影子一致性反馈与整体统计结论分开。配置独立保存在 `mindos/learning/calibration_policy.json`，不自动训练、调权重或改阈值。

新增证据按游标增量匹配，匹配结果物化到 `calibration_matches`，汇总缓存到 `calibration_snapshots`。数据变化时重聚合已匹配的统计记录，未变化读取缓存，不重放全体证据。新增预测也会使缓存失效。预测／结果／课程字段增加索引；模型调用不占有数据库写事务。进程中断后超过 15 分钟的处理中任务恢复为明确不可用，保留回答且不重新评分。

## 接口

- `POST /api/courses/{id}/authentic/start`：`atom_id`、`task_type`，可选 `difficulty`。
- `GET /api/courses/{id}/authentic/current`：恢复最近任务。
- `GET /api/courses/{id}/authentic/{task_id}`：课程所有权检查后的公开任务与结果。
- `POST .../{task_id}/draft`：`answer` 多行文本。
- `POST .../{task_id}/submit`：`answer`，评分与独立性不可由客户端指定。
- `POST .../{task_id}/hint`：不可撤销的提示标记。
- `POST .../{task_id}/defer`：保留草稿，暂缓任务。
- `GET /api/courses/{id}/calibration`：用户可理解的简化统计，不返回完整状态和回答。
- `GET /api/debug/learning/calibration`：仅 `MINDOS_DEBUG_LEARNING=1` 开放，当前用户范围。页面 URL 加 `?debug_learning=1` 可在报告底部显示开发统计入口。

数据均保存在本机，不新增遥测或外部分析服务。模型配置密钥仍由原加密存储管理。
